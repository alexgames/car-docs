# Контент-конвейер: ролики + инспирация (одна работа, два выхода)

Отдельная, самостоятельная задача — не смешивать с балансом/экономикой/спринтами 01/05. Источник — [[00-манифест-узкие-задания-и-контент-воронка]] и обсуждение 2026-07-18/19. Общий принцип: каждая единица работы производит одновременно и ролик, и рабочий контент/конфиг для игры — не двойная работа.

## Права на референсы — позиция зафиксирована, не блокер
Владелец считает, что подходит под добросовестное использование — не основная часть продукта, речь про историю дизайна, использование чужих изображений в этом контексте обычно. Мнение ассистента: добросовестное использование — оценка по фактам конкретного случая (США), не автоматическая защита, и в других юрисдикциях аналога может не быть вовсе; внутри платного коммерческого приложения это не гарантированно безопасно. Не блокирует работу — предпочитать по возможности более безопасные источники (архивные/пресс-фото производителей, общественное достояние, Creative Commons) там, где это не в ущерб качеству подборки.

## Разнообразие роликов через варианты одной машины
- [ ] Одна и та же машина (примерно) — 3 захода: свободный режим / по референсу / по чертежу и т.д. — снимать все варианты, раскидывать по разным дням публикации, не подряд.

## Гараж/сцена — в игре фича уже есть, но выключена (заметка на будущее)
В роликах для разнообразия используются разные виды гаража/сцены (фон, где стоит машина). В игре эта возможность **уже реализована, но сейчас выключена** — не нужно строить с нуля, нужно включить и добавить выбор/покупку. Не срочно, не блокирует текущую работу, но легко забыть. Дешёвая, вероятно, точка монетизации (косметика фона, тот же паттерн, что премиум-машины) — учитывать при следующем проходе по [[../sprints/баланс-и-монетизация]].

## Логистика и архив
- [ ] Найти старые данные для роликов и скрипты сборки — где-то на жёстком диске, не на компьютере.
- [ ] Купить/выделить отдельный жёсткий диск для хранения этих данных — не держать на рабочем компьютере.

## Апгрейд системы записи: JSON-реплей вместо кадров
- [ ] Записывать ролик не только кадрами (PNG-секвенция), но и как реплей-конфиг (JSON) — переиспользует систему, уже спроектированную для делегирования записи (см. [[../sprints/04-следующий-спринт-делегирование-роликов]]).
- [ ] Хранить как бэкап именно скрипт/реплей, не кучу кадров — можно перерендерить при необходимости, не пересобирать заново.

## Библиотека сценариев для роликов
- [ ] Собрать список всех возможных сценариев (используя уже имеющийся банк форматов, [[../10-маркетинг-банк-идей]]).
- [ ] Пример нового сценария: машина + 3 варианта обвеса → "выбери, какой нравится, в комментах" → в финале все 3 варианта одновременно крутятся на экране (без показа самой сборки).
- [ ] Под выбранные сценарии — доработать инструмент сборки ролика (поддержка нужных режимов монтажа).

## Опционально: промокоды в роликах
- [ ] Продумать/написать систему вклеивания промокода в уже отснятые кадры постфактум (обогащение готовой секвенции, не пересъёмка).
- [ ] Ролик = записанная секвенция + конфиг с указанием музыкального трека — собирается автоматически, но можно пересобрать вручную с кодом при необходимости.
- [ ] Зарезервировать часть игрового контента специально под промокоды (социальная механика) — см. [[../hypotheses/14-промокоды-чертеж-паззл]] за деталями UI.
- **Условие:** реализовывать промокоды имеет смысл, если базовая версия игры реально заработает (владелец готов добавить неделю на это как на подтверждённую, не гипотетическую фичу — с ИИ реализация быстрая).

## Дейлики из готового контента (чертежи + оценка дизайна)
Использует контент, оставшийся от старого режима нарратива (уже существует, не нужно создавать заново):
- [ ] Чертежи (Orders) — переупаковать как дейлики.
- [ ] Задания "собери дизайн с оценкой" (есть явно хорошие/плохие варианты по существующим весам) — в роликах показывать сборку на 4-5 звёзд, зрителям предлагать собрать самим.
- [ ] На выходе с каждого такого ролика — сразу рабочий конфиг дейлика для игры, не просто видео.
- [ ] Серверный алгоритм ротации: какой дейлик показывать когда — дейлики по оценке дизайна могут повторяться раз в несколько месяцев без проблем ("никто не заметит, а если заметит — не страшно").
- Цель дейликов такого типа — оживлять/напоминать про стиль, не разовая акция.

## Текстуры как дейлик-контент, потом ПРО-инструмент (добавлено 2026-07-19)
Инструмент текстур уже технически есть (пример: текстура "пицца" сейчас висит в первом стиле, Urban). Проблема: такая шуточная текстура постоянно доступной в базовом стиле сбивает тон — Urban всерьёз учит истории дизайна (референсы/история стиля), а пицца туда не вписывается.

- [ ] Убрать "случайные" текстуры (пицца и т.д.) из базовых стилей как постоянную опцию
- [ ] Добавить как контент дейликов: пицца (доставка пиццы — City-стиль подходит по смыслу), камуфляж, арт-текстуры в стиле разных художников
- [ ] Протестировать фичу через дейлики — дёшево, не блокирует остальное
- [ ] При подтверждении интереса — сделать полноценным ПРО-инструментом (см. [[../hypotheses/13-про-режим-создай-свой-стиль]], раздел "дикий" пул — арт-текстуры и камуфляж туда напрашивались с самого начала)

## Порядок работы
Делать последовательно, не разбрасываясь между пунктами одновременно — явное решение владельца, чтобы не потерять фокус.

## Отношение к сроку релиза
Если ядро игры (баланс, экран выбора режима) будет ощущаться рабочим и уверенным по ходу дела — владелец готов сознательно отложить релиз ещё на месяц ради усиления этим контент-конвейером: больше уверенности, больше данных, более мощный запуск. Это не срыв срока, а сознательный выбор при условии, что ядро подтверждено.
