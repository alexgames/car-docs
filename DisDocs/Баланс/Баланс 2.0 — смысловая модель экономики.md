# Баланс 2.0 — смысловая модель экономики

Статус: рабочий документ. Здесь сначала фиксируются продуктовые причины экономики; цифры, формулы и конфиги — только следствие этих решений.

## 1. Главная мысль

Мы не начинаем с цены детали, пакета монет или целевого ARPPU.

Игра должна регулярно давать игроку новый выразительный результат: машину, стиль, приём, сцену, инструмент или повод показать работу. Экономика управляет темпом таких результатов, выбором между ними и редкими моментами покупки. Она не должна искусственно урезать базовое творчество.

Последовательность принятия решений:

1. Какой творческий опыт должен получить игрок.
2. Какими наборами контента этот опыт обеспечивается.
3. Как часто игрок получает эти наборы бесплатно.
4. Сколько времени занимает желаемая цель при фокусе на ней.
5. Где находятся добровольные ускорение, коллекционирование и эксклюзивность.
6. Выдерживает ли модель бизнес-цели и симуляцию разных игроков.

## 2. Разделяем три слоя

### Продуктовый слой — «зачем игрок возвращается»

Это не экономика. Здесь задаются:

- первые сильные результаты и первая машина, которой хочется поделиться;
- новые стили, визуальные направления и новые творческие возможности;
- темп: быстрое начало, затем более редкие, но заметные открытия;
- разные мотивации: свободно поэкспериментировать, собрать любимый стиль, освоить инструмент, коллекционировать, участвовать в промо и сообществе.

Единица планирования — не отдельная фара, а **творческая цель**: например, «собрать убедительный neo-retro GT», «получить возможность снимать машину в новой сцене», «сделать первый осмысленный вариант любимого стиля».

### Экономический слой — «каким путём к этому прийти»

Здесь определяются источники и траты валют, цены, временные цели, доступность контента и правила выдачи. Его задача — дать понятный путь к цели и сделать дефицит управляемым, а не случайным.

### Бизнес-слой — «может ли это окупаться»

Здесь живут цены IAP, конверсия, ARPPU, реклама, прогноз дохода и варианты A/B. Это проверка жизнеспособности продуктовой модели, а не источник цен на конкретные предметы.

## 3. Что именно должно быть в продуктовой гипотезе

Продуктовая гипотеза — не «dolphin ARPPU = $20». Это обещание игрового пути.

Для каждого периода активных дней нужно описать:

| Период | Что игрок умеет / получает | Какой результат создаёт | Почему возвращается |
| --- | --- | --- | --- |
| 1–3 | | | |
| 4–10 | | | |
| 11–30 | | | |
| 31–70 | | | |
| дальше | | | |

Рабочие продуктовые вопросы:

- На какой день игрок делает первую машину, которой не стыдно поделиться?
- Когда появляется первая желанная альтернатива, а не просто очередная деталь?
- Как часто возникает причина вернуться и попробовать ещё раз?
- Когда игрок впервые получает новый стиль, инструмент, сцену или другой заметный творческий сдвиг?
- Что в игре остаётся свободным всегда, потому что это core gameplay?
- Какие открытия должны быть редкими, чтобы оставаться событием?

## 4. Каталог контента: не одна оценка, а несколько независимых свойств

Оценка 1–10 полезна, но это только субъективная желанность. Она не должна автоматически превращаться в цену или валюту.

Для каждой единицы или набора контента предлагается хранить:

| Поле | Смысл |
| --- | --- |
| `contentId`, `type` | Техническая идентификация |
| `creativeRole` | core / variety / mastery / collectible |
| `desirability` 1–10 | Насколько игроку хочется именно это |
| `learningLoad` | Насколько нужно разобраться, чтобы применить хорошо |
| `dependency` | Что должно быть открыто вместе с ним, чтобы результат был красивым |
| `economyRole` | free / soft / hard / real / promo / event |
| `releaseBand` | Когда это вообще может появиться по активным дням |
| `bundleId` | К какой творческой цели или комплекту относится |
| `notes` | Почему решение принято вручную |

Ключевое правило: сложность влияет прежде всего на время и контекст выдачи. Она не обязана делать предмет дорогим. Самый желанный предмет может быть бесплатной наградой за ранний успех, промо-секретом или реальной покупкой — это разные продуктовые роли.

## 5. Наборы важнее одиночных предметов

В CarDesign ценность создаёт сочетание. Новый корпус без подходящих колёс, оптики или обвеса может дать плохой опыт, даже если формально игрок что-то «получил».

Поэтому сначала составляются **creative baskets** — наборы, которые действительно позволяют собрать образ. Например:

- базовый набор стиля: достаточно для первой хорошей машины;
- набор вариативности: позволяет сделать второй характер внутри того же стиля;
- набор мастерства: расширяет язык формы и съёмки;
- коллекционный набор: красивый, редкий, но не необходимый для core-опыта.

Цена, выдача и монетизация должны проверяться на уровне такого результата, затем раскладываться на предметы.

## 6. Роли валют и каналов

| Канал | Роль в опыте |
| --- | --- |
| Бесплатно | Основа творчества и уверенность, что в игру можно играть полноценно |
| Soft currency | Накопление к выбранной цели; игрок выбирает, что открыть раньше |
| Hard currency | Немедленное решение желанной задачи или покупка редкой вещи; не второй обязательный гринд |
| Real money | Понятный оффер, коллекционная/премиальная ценность или удобный пакет; не вырезанный core gameplay |
| Promo | Эксклюзивность, контент-маркетинг и причина следить за внешней экосистемой |
| Event | Временный творческий повод, а не просто ещё одна валюта |

В версии 2 бусты отключены: они добавляют ещё одну ось выбора до того, как доказана ценность основной экономики.

## 7. Как выводить цены soft currency

Цена soft-предмета должна начинаться с желаемого времени до цели, а не с процента «бюджета игрока».

Базовая формула:

`цена цели = монеты, которые сфокусированный игрок реально может потратить за N активных дней`

Важно слово «сфокусированный». Если игрок копит только на стиль, а формула считает, что он параллельно обязан потратить 80% монет на другое, стиль откроется намного раньше заданного срока.

Параллельные траты моделируются симулятором как разные типы поведения, а не прячутся внутрь цены:

- фокусный игрок копит на конкретную цель;
- естественный игрок периодически покупает мелкие вещи;
- коллекционер покупает почти всё доступное;
- платящий ускоряет конкретные моменты.

Так становится видно, где «цель на 7 дней» на самом деле открывается за полтора дня.

## 8. Как связывать hard и реальные деньги

Магазин задаёт долларовый якорь, но не назначает цену предмета напрямую.

Порядок другой:

1. Назначить контенту желаемый долларовый класс: импульсная покупка, маленький подарок себе, значимый набор, премиальный коллекционный объект.
2. Выбрать пакет hard currency, который делает этот класс понятным.
3. Проверить, сколько hard currency игрок получает бесплатно и не обесценивает ли это покупку.
4. Проверить в симуляции, что free-to-play путь остаётся полноценным.

ARPPU и конверсия нужны затем, чтобы проверить набор офферов и прогноз, но не чтобы выводить цену фары из среднего дохода плательщика.

## 9. Что означает текущий экран «Продукт» в Balance Lab

Экран логично собрать не как последовательность формул, а как главный дашборд решений:

1. **Продуктовые цели** — таблица по активным дням и творческим результатам.
2. **Каталог и наборы** — ручная оценка контента, его роль и зависимости.
3. **Ритм бесплатной выдачи** — сколько и каких возможностей игрок получает по периодам.
4. **Правила ценообразования** — цели по времени, ценовые классы и коэффициенты, а не ручная цена каждой фары.
5. **Политика валют и монетизации** — что может быть soft/hard/real/promo.
6. **Генерация игрового конфига** — сохраняет конкретный баланс-профиль.
7. **Симуляция и валидатор** — отвечает, достигнуты ли обещания продуктовой гипотезы.
8. **Бизнес-проверка** — магазин, реклама и прогноз; отдельный слой, не следующий шаг к цене.

## 10. Что пока не нужно фиксировать цифрами

Пока не определены творческие цели и состав наборов, не стоит считать окончательными:

- конкретные цены отдельных предметов;
- ежедневный доход монет;
- награды дейликов и Арены;
- доли трат по категориям;
- курс soft ↔ hard;
- прогноз ARPPU.

Они остаются стартовыми гипотезами для симуляции, а не решениями.

## 11. Ближайшее совместное решение

Следующий шаг — не формула, а короткий список из 10–15 творческих целей на первые 30 активных дней. Для каждой надо определить:

1. Что игрок сможет создать или сделать.
2. Какие компоненты/наборы для этого нужны.
3. Это core, вариативность, мастерство или коллекционирование.
4. Целевой активный день.
5. Какой путь допустим: бесплатно, soft, hard, real, promo.

После этого можно честно задать первый контентный конфиг и только затем включать генерацию цен.
