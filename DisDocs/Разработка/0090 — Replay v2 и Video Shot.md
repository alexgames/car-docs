# 0090 — Replay v2 и Video Shot

Связано: [[0020 — Запись видео (инструмент)]] · [[0019 — Видео-дейлики-рефералы]] · [[0072 — Видео: сводный чек-лист]]

## Решение

Разделить два формата с разной ответственностью:

- **Replay v2** — компактная история действий игрока и состояний машины. Это источник материала, а не готовая режиссура.
- **Video Shot v1** — постановочный монтажный кадр: выбирает состояние из реплея или `CarData`, управляет машиной, камерой, `LookAt` и экспортом.

```text
Replay v1/v2 или CarData
          ↓
    CarStateResolver
          ↓
      Video Shot
          ↓
 машина + камера + LookAt
          ↓
 PNG-секвенция одного монтажного кадра
          ↓
 внешний монтаж / раскладка нескольких кадров
```

Сложный монтажный кадр обычно содержит одну машину. Несколько ракурсов одной машины рендерятся отдельными камерами/секвенциями. Несколько разных машин сначала рендерятся отдельно, затем склеиваются внешним скриптом. Поддержка нескольких независимых игровых сцен внутри одного рендера сейчас не нужна.

Нулевой кадр реплея должен содержать глубокий снимок стартового `CarData`, а не только `LevelData`. В снимок входят `formula`, полный `DeformConfig`, тюнинг с locator-ами, материалы и цвета. Последующие события являются изменениями относительно этого состояния. Без стартового deform locator-ы обвеса применяются к базовой форме кузова и визуально оказываются внутри неё.

---

## Термины и имена

### Данные

- `ReplayDocument` — корневой документ реплея.
- `ReplayHeader` — версия, идентификатор, время, сведения об источнике.
- `ReplayEvent` — дискретное изменение игрового состояния.
- `ReplayMotionTrack` — опциональная траектория реального непрерывного действия игрока.
- `ReplayMotionSample` — прореженная точка такой траектории.
- `CarStateSnapshot` — полное состояние машины в определённый момент.
- `VideoShot` — один постановочный монтажный кадр.
- `ShotTrack` — постановочная анимация внутри `VideoShot`.
- `CameraPoseKey` — ключ положения камеры.
- `LookAtKey` — отдельный ключ точки/объекта, на который смотрит камера.
- `ShotTimeMap` — соответствие времени монтажного кадра времени исходного реплея.

### Runtime

- `ReplayRecorder` — записывает `ReplayDocument`.
- `ReplayCompactor` — прореживает или удаляет тяжёлые motion-треки.
- `ReplayMigrator` — переводит v1 в текущую внутреннюю модель.
- `CarStateResolver` — восстанавливает состояние машины на произвольном времени.
- `ShotEvaluator` — вычисляет постановочные изменения на времени кадра.
- `SmartCameraRig` — вычисляет камеру с учётом габаритов и объекта внимания.
- `ShotPreviewController` — ползунок, play/pause и покадровая проверка.
- `FrameExporter` — PNG сейчас, видеоэнкодер позже.

Текущие `ReplaySaver` и `ReplayPlayer` не переименовывать сразу. Сначала новые классы должны жить рядом и читать старые данные через адаптер.

## Replay v2

### Назначение

Replay v2 обязан:

1. Сохранить достаточно данных, чтобы восстановить итоговые и ключевые состояния машины.
2. Позволить получить `CarState` на произвольном времени.
3. При необходимости сохранить реальное движение игрока.
4. Оставаться компактным: камера и подробные движения являются опциональными.
5. Загружаться независимо от настроек монтажа и скорости будущего ролика.

Replay не обязан хранить каждый отображённый кадр и не обязан диктовать будущую камеру проморолика.

### Корневая структура

```json
{
  "schema": "car-design.replay",
  "version": 2,
  "id": "work-123-replay",
  "duration": 84.27,
  "recordingProfile": "gameplayCompact",
  "initialState": {
    "kind": "levelData",
    "data": {}
  },
  "events": [],
  "motionTracks": [],
  "checkpoints": []
}
```

### Профили записи

```text
gameplayCompact
— дискретные события и финальные состояния действий;
— без камеры;
— без промежуточных точек TuningPlacer.

gameplayMotion
— gameplayCompact;
— реальные движения TuningPlacer с прореживанием;
— камера обычно выключена.

promoSource
— движения TuningPlacer;
— при необходимости исходная камера;
— более точные пороги прореживания.
```

Профиль — это настройка записи, а не отдельная версия формата. Любой motion-трек может отсутствовать или быть удалён позже без потери итогового состояния машины.

### Дискретные события

В v2 сохранить существующие события, но использовать стабильное строковое имя типа:

```json
{
  "time": 12.4,
  "type": "tuning.locator.commit",
  "target": "light-front-left",
  "payload": {
    "locator": {}
  }
}
```

Основные группы:

```text
part.variant.set
tuning.item.set
tuning.locator.commit
body.deformation.commit
body.color.set
body.material.set
body.texture.set
car.clearance.set
car.width.set
wheel.size.set
view.mode.set
```

`tuning.item.set` означает выбор/создание варианта тюнинга. `tuning.locator.commit` означает подтверждённое положение уже созданной детали после отпускания. Это разные события; существующее имя Unity-события `OnTunPlaced` не использовать как имя контракта, потому что сейчас оно вызывается при создании prefab, а не при завершении drag.

Новые типы не должны зависеть от порядкового номера C# enum. Старые числовые типы v1 преобразует `ReplayMigrator`.

### Реальное движение TuningPlacer

Движение хранится отдельным `ReplayMotionTrack`, а не сотнями обычных событий:

```json
{
  "id": "motion-17",
  "type": "tuning.locator.motion",
  "target": "light-front-left",
  "startTime": 20.1,
  "endTime": 21.8,
  "interpolation": "linear",
  "samples": [
    { "time": 0.0, "locator": {} },
    { "time": 0.23, "locator": {} },
    { "time": 0.61, "locator": {} },
    { "time": 1.7, "locator": {} }
  ]
}
```

Запись:

```text
StartDrag → открыть motion-трек, сохранить начальный Locator,
            временно восстановить корпус без вырезов
Drag      → добавлять sample по порогам; двигать деталь без пересборки отверстий
StopDrag  → сохранить последний sample, обязательный locator.commit,
            затем один раз перестроить вырезы
```

Перестроение вырезов — обязательный side effect применения `tuning.locator.commit`, а не отдельное пользовательское событие реплея. И запись, и воспроизведение должны соблюдать порядок:

```text
применить финальный Locator
→ синхронизировать transform/physics при необходимости
→ RebuildCutoutsIfActive
→ считать состояние кадра готовым к рендеру
```

Во время промежуточных samples вырезы не пересчитываются. Это соответствует поведению `TuningPlacer`: на начале drag возвращается чистый корпус, на отпускании вырезы создаются заново. Применение состояния вынесено в независимый `TuningPlacementService`: им пользуются игровой `TuningPlacer`, `ReplayPlayer` и будущие постановочные сценарии. Реплей не активирует `TuningPlacer`, не обращается к его UI, камере, raycast или undo; после `TunLocator` он вызывает общий commit с синхронизацией transform и перестроением вырезов.

Sample добавляется, если выполнено хотя бы одно условие:

- прошло заданное максимальное время;
- позиция изменилась больше допуска;
- вращение изменилось больше допуска;
- масштаб изменился больше допуска.

После завершения `ReplayCompactor` может повторно упростить траекторию по допустимой визуальной ошибке.

Скорость не является обязательной частью каждого записанного sample: её можно вычислить из соседних точек. Если после прореживания важно сохранить характер реального движения, `ReplayCompactor` может записать опциональные входящую и исходящую касательные ключа (`inTangent`, `outTangent`). Это полезнее одного `velocity`: движение до и после ключа может иметь разную скорость и направление.

Если трек оказался слишком большим, допустимы уровни деградации:

```text
точные samples
→ более редкие samples
→ только начало + конец
→ удалить motion-трек
```

`tuning.locator.commit` остаётся всегда. Поэтому удаление движения не меняет итоговую машину.

### Камера игрока

Камера хранится таким же опциональным motion-треком:

```json
{
  "type": "camera.orbit.motion",
  "samples": [
    {
      "time": 0.0,
      "orbit": { "horizontal": 0, "vertical": 12, "distance": 7.5 },
      "lookAt": { "binding": "car.center" }
    }
  ]
}
```

По умолчанию `gameplayCompact` камеру не пишет. Для проморолика `VideoShot` обычно создаёт новую постановочную камеру. Если исходная камера была записана, её можно использовать как референс или источник ключей.

### Checkpoints

Для первого этапа checkpoints необязательны. `CarStateResolver` может восстановить состояние от начала применением событий.

Если произвольный seek окажется медленным, периодически сохранять `CarStateSnapshot`:

```text
найти checkpoint ≤ requestedTime
→ применить события после checkpoint
→ получить CarState(requestedTime)
```

Checkpoints являются кэшем: их можно удалить и построить заново.

### Время

Времена исходного реплея неизменяемы. Существующий `CompressTime()` нельзя применять к загруженному документу на месте.

Ускорение и удаление пауз выполняет `ShotTimeMap`:

```text
shotTime → replayTime
```

Это позволяет собрать из одного реплея несколько роликов с разным темпом.

## Video Shot v1

### Назначение

`VideoShot` описывает один постановочный монтажный кадр. Он может:

- взять состояние из реплея в произвольный момент;
- взять обычный `CarData` без реплея;
- воспроизвести часть действий игрока;
- игнорировать порядок действий игрока;
- вращать машину;
- менять обвес в заданных точках;
- плавно показать деформацию;
- воспроизвести записанное или постановочное движение детали;
- управлять камерой и `LookAt` отдельными ключами.

### Корневая структура

```json
{
  "schema": "car-design.video-shot",
  "version": 1,
  "id": "headlights-reveal-01",
  "duration": 6.0,
  "source": {
    "kind": "replay",
    "uri": "work-123-replay.json",
    "atTime": 48.2
  },
  "timeMap": [],
  "tracks": [],
  "camera": {},
  "output": {
    "width": 1080,
    "height": 1920,
    "fps": 30,
    "alpha": false
  }
}
```

### Источники

```text
ReplaySource
— состояние из Replay v1/v2.

CarDataSource
— готовая сохранённая машина без истории.
```

Внутри runtime оба источника дают одинаковый `CarState`.

### Постановочные треки

Минимальный набор:

```text
CarRotationTrack
PartVariantTrack
PartPlacementTrack
DeformationTrack
ColorTrack
CameraPoseTrack
LookAtTrack
```

`PartPlacementTrack` имеет два источника ключей:

```text
recorded — скопировать реальный ReplayMotionTrack;
directed — задать ключи вручную в Shot Editor.
```

После копирования recorded-трек становится обычным редактируемым треком Shot: его можно ускорить, сгладить, обрезать или заменить.

### Камера и LookAt

Положение камеры и точка взгляда — независимые треки:

```json
{
  "camera": {
    "poseTrack": {
      "keys": [
        { "time": 0.0, "position": [5, 2, -7], "fov": 42, "ease": "smooth" },
        { "time": 2.4, "position": [2, 1, -4], "fov": 36, "ease": "smooth" }
      ]
    },
    "lookAtTrack": {
      "keys": [
        { "time": 0.0, "binding": "car.center" },
        { "time": 1.8, "binding": "part", "target": "light-front-left" },
        { "time": 3.0, "binding": "car.center" }
      ]
    }
  }
}
```

Ключ позиции может дополнительно содержать касательные:

```json
{
  "time": 2.4,
  "position": [2, 1, -4],
  "inTangent": [-0.8, 0.1, 1.2],
  "outTangent": [-0.2, 0.0, 0.7],
  "tangentMode": "auto",
  "fov": 36
}
```

Правила:

- при отсутствии касательных интерполяция вычисляет их автоматически из соседних ключей;
- `linear` и `hold` касательные не используют;
- `smooth` может использовать автоматические или сохранённые касательные;
- `tangentMode: auto` пересчитывает их при перемещении ключа;
- `tangentMode: recorded` сохраняет динамику записанного движения;
- `tangentMode: free` позволяет независимо менять входящую и исходящую касательные;
- для камеры и позиции детали касательные измеряются в единицах пространства в секунду;
- для `LookAt` используются собственные касательные, независимо от движения камеры;
- скорость вращения и масштаба добавляется только при реальной необходимости, а не в базовый контракт каждого ключа.

Таким образом простой ключ остаётся компактным, но записанная камера или движение детали при необходимости сохраняют не только точки, но и характер прохождения через них.

Поддерживаемые `LookAt` binding:

```text
worldPoint
car.center
car.front
car.rear
car.boundsPoint
part
manualTarget
```

Shot Editor редактирует ключевые точки, а не ручные сплайны. Между ключами система строит траекторию автоматически. Минимальные режимы интерполяции: `linear`, `smooth`, `hold`.

### SmartCameraRig

Умная камера использует реальные bounds видимых частей машины и смысловые anchors. Она должна учитывать:

- длину и высоту конкретной машины;
- соотношение сторон результата;
- safe frame;
- объект внимания;
- запас для движения и деформации.

Первые режимы:

```text
fitWholeCar
orbitWholeCar
focusPart
followPlacement
manualKeys
```

Автоматический режим может сгенерировать `CameraPoseKey` и `LookAtKey`, после чего пользователь вручную исправляет только нужные точки.

## Shot Editor

Минимальный процесс:

1. Выбрать Replay или CarData.
2. Создать `VideoShot`.
3. Двигать ползунок `shotTime`.
4. Поставить камеру и `LookAt Target`.
5. Нажать `Add Key` или `Update Key`.
6. Добавить треки машины/деталей.
7. Проверить play/pause и покадрово.
8. Отрендерить PNG-секвенцию.

Необходимый UI:

```text
Play / Pause
Previous frame / Next frame
Time slider
Add / Update / Delete camera key
Add / Update / Delete LookAt key
Interpolation selector
Preview camera toggle
Render PNG
```

Unity Timeline можно позже подключить как адаптер или дополнительный визуализатор. Каноническими данными остаются `VideoShot` и его JSON/serializable-модель, чтобы один и тот же Shot работал в Editor, игре и пакетном рендере.

## Совместимость с Replay v1

1. Сервер продолжает принимать старый replay JSON.
2. Загрузчик сначала читает поле `version`.
3. `version = 1` преобразуется `ReplayMigrator` во внутреннюю модель v2.
4. Старые числовые `ReplayEventType` переводятся в строковые type ID.
5. Отсутствующая камера и motion-треки считаются нормальным состоянием.
6. Исходный v1-файл не изменяется при проигрывании или сжатии времени.

## Критерий первого рабочего среза

Из существующего replay JSON можно:

1. Открыть машину в произвольном состоянии.
2. Создать шестисекундный `VideoShot`.
3. Сделать один оборот машины.
4. Задать 3–4 ключа камеры и отдельно 2–3 ключа `LookAt`.
5. Показать установку одной детали реальным recorded-треком или directed-треком.
6. Перемещаться ползунком вперёд и назад с одинаковым результатом.
7. Получить детерминированную PNG-секвенцию с заданным FPS.
