# 0054 — Обвес и вырезы в кузове

## Проблема

Текущий обвес собирался как широкая пачка разнородных деталей без строгих продуктовых целей по стилям и моделям. Сейчас видны конкретные пробелы: не хватает нужных фар, решёток, воздухозаборников, бамперов и других деталей, которые делают автомобиль законченным.

Большинство реальных деталей конструктивно врезаны в кузов. Простое наложение prefab поверх поверхности оставляет игрушечное ощущение. Возможность делать отверстия и посадочные зоны может дать больший визуальный скачок, чем добавление большого количества новых накладных деталей.

## Направления исследования

### Вырезы

- булевы операции над low-poly/control mesh до OpenSubdiv;
- заранее размеченные параметрические отверстия;
- маска/шейдерный cutout или depth-only трюк как дешёвая иллюзия;
- готовые посадочные панели, заменяющие часть кузова;
- ограниченный набор примитивов: цилиндр, capsule, rounded rectangle;
- влияние на topology, Stencil Tables, сохранения, коллайдеры и мобильную производительность.

Практичный первый прототип: цилиндрические отверстия для круглых фар. Разметить порядка 80 фар допустимо, если одна разметка надёжно создаёт посадку и существенно повышает качество всех машин.

### Производство новых деталей

- поиск готовых лицензируемых наборов;
- извлечение деталей из купленных полных моделей с проверкой лицензии;
- процедурная сборка простых категорий из примитивов и профилей;
- фотограмметрия/запечённые плоские фары там, где глубину можно имитировать материалом;
- AI text/image-to-3D только как исследование: оценивать topology, UV, лицензию, повторяемость стиля и время ручной очистки;
- приоритет не количеству, а матрице недостающих деталей по стилям и эпохам.

Особенно осторожно с бесплатными паками на CGTrader — многие такие лицензии этого явно не покрывают. Ложится на уже существующий пункт 202 чек-листа ниже.

**AI image-to-3D генераторы (2026, к тому же пункту 201):**
- [Tripo AI](https://www.tripo3d.ai/) — лучшая топология под геймдев: чистый quad-mesh из коробки, quad remesh одной кнопкой, модель за ~8 сек, PBR по умолчанию, дешевле для быстрой итерации.
- [Meshy](https://www.meshy.ai/) — самый сбалансированный: за один проход отдаёт уже текстурированную PBR-модель без отдельного шага текстурирования; по бенчмаркам чуть точнее по деталям поверхности на одиночном фото.
- [Rodin](https://hyperhuman.deemos.com/rodin) — упор на фотореалистичную детализацию (10+ млн полигонов), избыточно для мобильной стилизации, но вариант для референса высокой точности.

Однозначного "лучшего под машины" нет ни у одного — гладкие автомобильные панели (капот, крыло) как раз то, где image-to-3D по одиночному фото чаще всего даёт неровности вместо идеально гладкой поверхности; качество сильно зависит от количества/ракурсов исходных фото, не только от выбора инструмента.

Лицензия — отдельная повторяющаяся статья расходов, не разовая: у Meshy бесплатный тариф (~10 моделей/мес) **некоммерческий**, коммерческая лицензия только на платном Pro (~$20/мес); у Tripo похожая логика. Учитывать в расчёте стоимости по пункту 202, не как разовую покупку пака.

## Критерий решения

Продолжать геометрические вырезы, только если прототип заметно повышает качество машины, не ломает параметрическую сборку и допускает быстрый authoring десятков деталей. Иначе использовать посадочные панели или визуальную имитацию как контролируемый компромисс.

## Editor-инструмент для cutter

Отдельное editor-окно берёт `Selection.activeGameObject` как верхний root открытого prefab. Именно его локальные оси описывают направление установки детали. Вложенный пустой `GameObject` может содержать импортную коррекцию поворота, поэтому его выбирать нельзя. Вложенность position/rotation/scale всех mesh-объектов пересчитывается в координаты этого root. В сам prefab не добавляются служебные MonoBehaviour и настройки: инструмент генерирует или обновляет только дочерний mesh-объект с заданным имем (`cutter` по умолчанию).

Из исходного объёма исключаются сам `cutter` и любые объекты/иерархии с маркером `_nocut` в имени. Это продолжает уже используемую схему `_noprint`, `_noffd`, `_dsp`, `_hi`, `_lo`. Маркер можно поставить на родителя, чтобы исключить всю его ветку.

Первая версия — выпуклая силуэтная призма:

1. Собрать вершины всех активных `MeshFilter` в prefab, кроме самого `cutter`.
2. Спроецировать их на плоскость, перпендикулярную направлению установки.
3. Построить 2D convex hull, уменьшить его на `Outline Inset` и упростить до заданного числа точек.
4. Экструдировать контур вдоль локальной нормали prefab.
5. Сохранить обычный Mesh asset. Если нужна ручная доводка, его можно ProBuilderize и двигать точки.

Ориентир: 6–16 точек контура, обычно 20–60 треугольников. Мягкий предел — 32 точки. Для текущего CPU-вырезания это дёшево; большая плотность не даёт заметного выигрыша.

3D convex hull можно добавить вторым режимом для сложных фар, но для решёток и большинства фар силуэтная призма проще и надёжнее.

## Conform-детали

Задача: одна и та же решётка, бампер или фара должны мягко подстраиваться под разную кривизну кузова. Функция настраивается для каждого prefab и по умолчанию выключена.

Предлагаемый алгоритм:

1. После установки prefab на locator создать на его 2D-плоскости сетку, например 4×3, 6×4 или 8×6.
2. Из каждой точки послать параллельный ray вдоль направления установки и запомнить глубину до кузова.
3. Заполнить промахи ближайшими валидными значениями, затем слегка сгладить depth field.
4. Для каждой вершины детали билинейно интерполировать смещение по сетке.
5. Сдвигать вершины **только вдоль оси установки**. Вершины одной «колонки» получают одинаковое смещение: так сохраняются толщина, внутренние слои и материальные части.

Настройки prefab: `Conform Enabled`, размер сетки, `Strength`, `Surface Offset`, максимальное смещение и falloff к краям. Для жёстких креплений позже можно добавить vertex mask, но для MVP достаточно общего falloff.

Порядок runtime-операций: исходный mesh детали → locator transform → conform к кузову → cutter/вырез. При StartDrag нужно возвращать исходный mesh, при StopDrag — повторять conform и вырез.

Это дешёвая операция: десятки raycast на событие и один линейный проход по вершинам. На GPU выносить не нужно. Первый прототип стоит делать на решётке или бампере; фара сложнее из-за внутренних жёстких частей.

### Реализация 1D-профиля

Первая runtime-версия сделана для тонких решёток и бамперов:

- `TuningConformSettings` добавляется только на root тех prefab, которым нужен conform;
- локальная `X` prefab считается горизонтальной осью профиля, локальная `Z` — глубиной;
- по всей ширине снимается полный профиль кузова, без зеркального копирования половины, поэтому в центре не возникает излома;
- промахи между лучами интерполируются, за границами найденного участка профиль линейно экстраполируется;
- центральная глубина остаётся неподвижной, остальные вершины смещаются относительно неё только по локальной `Z`;
- исходный mesh asset не меняется: для экземпляра создаётся runtime-копия и хранится исходный массив вершин;
- при начале drag исходная форма детали восстанавливается; при отпускании сначала восстанавливается цельный кузов, затем пересчитывается conform и только после этого применяются cutter-отверстия.

В настройках есть dropdown режима:

- `Profile1D` — одна горизонтальная линия, линейная интерполяция по ширине;
- `Surface2D` — сетка `Samples X × Samples Y`, билинейная интерполяция смещения по ширине и высоте.

Общие параметры: `Ray Distance`, `Strength`; для 1D дополнительно используется `Sample Height`. Кнопка `Set Defaults` в инспекторе возвращает кодовые значения параметров обоих режимов. `bt_grill807` оставлен в проверенном режиме `Profile1D`, тестовый prefab `bt_grill823` использует `Surface2D` со стартовой сеткой 9×5 лучей. Промахи сначала заполняются внутри каждой строки, затем интерполируются или экстраполируются между строками. Следующая итерация: визуализация сетки и управляемое сглаживание depth field.

Экспериментальный параметр `Follow Surface Normal` меняет способ переноса толщины детали. При `0` вершины параллельно сдвигаются по локальной `Z`; при `1` рельеф и толщина откладываются вдоль нормали depth field, вычисленной из его производных. Это создаёт настоящий изгиб поперечного сечения по радиусу и одновременно поворачивает исходные нормали меша. Для `bt_grill807` значение оставлено `0`, для тестового `bt_grill823` установлено `1`.

## Bend authoring prefab

Для постоянного выпрямления исходных деталей добавлен editor-компонент `TuningBendAuthoring`. Первая версия работает с одной горизонтальной полилинией в локальной плоскости `X/Z`:

1. `Create Guide From Mesh` автоматически строит стартовую линию по геометрии на высоте `Guide Height`.
2. Оранжевые точки редактируются в Scene View.
3. `Bake Straightened Meshes` вычитает профиль линии из локальной `Z` всех дочерних мешей, кроме `cutter`.
4. Результаты сохраняются рядом с prefab в `GeneratedBendMeshes` и назначаются его `MeshFilter`.
5. `Restore Original Meshes` возвращает исходные Mesh assets; повторный Bake всегда считается от оригиналов и не накапливает деформацию.

Параметр `Strength` позволяет частично распрямить деталь. Первый тестовый prefab — `bt_grill823`. Следующий этап после проверки одной линии: коррекция нормалей, preview без Bake и вторая полилиния по вертикальной оси.
