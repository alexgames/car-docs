# 0052 — Android: размер сборки и запуск

## Цель

Получить воспроизводимую Android-сборку, которая быстро запускается без сервера, имеет объяснимый размер и оставляет запас для роста материалов и контента.

## Базовая точка

- APK: около 510 MiB (535 MB в десятичном отображении).
- `data.unity3d`: 446,5 MB внутри APK — главный источник размера.
- Две архитектуры IL2CPP добавляют примерно 53 MB в сжатом виде; это заметно, но не объясняет основной объём.
- Первый запуск на устройстве занимал минуты; повторный запуск однажды не завершился.
- Последний Unity Build Report сделан через Script Only Build и не содержит списка использованных ассетов.
- `Assets/Addr2/Resources` содержит около 160 MB исходников встроенных колёс, шин и салона. Это используемый runtime-контент, не готовый к удалению, но часть старых текстур не имеет Android override и импортируется заметно крупнее соседних.
- 390 явных записей Addressables проверены по GUID: ни одна физически не лежит в папке `Resources`. Прямого двойного включения одного asset как Resources и Addressable не найдено; дубли зависимостей между бандлами ещё требуют Addressables Build Layout.

## Критерии готовности текущей версии

- Размер объясняется отчётом; самые крупные позиции имеют продуктовую причину или вынесены из сборки.
- Холодный и повторный запуск стабильно доходят до интерфейса на тестовом Android-устройстве.
- Стартовая машина открывается без сети и без доступного Addressables-сервера.
- Отложенные оптимизации записаны отдельно и не блокируют внутренний тест Google Play.

## Текущий вывод

Android-часть достаточна для внутренней публикации. Детальный cold-start аудит и Addressables duplicates не блокируют текущий билд. Следующая обязательная платформенная проверка — iOS. Работа с Addressables duplicates возвращается вместе с реорганизацией материалов, потому что именно общие материалы и их зависимости сейчас образуют основную неразмеченную систему контента.

## Не делать без измерений

- Не удалять `Resources` целиком: там находятся встроенные исключения для стартовой машины и офлайн-запуска.
- Не оценивать вклад PNG/PSD по размеру исходника: в сборку попадает импортированный и сжатый ресурс.
- Не включать Deep Profiling для первого замера: он сильно искажает старт.
