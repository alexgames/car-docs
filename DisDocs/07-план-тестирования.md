# План тестирования перед релончем (robust-версия)

Связано с: [Текущий спринт](sprints/01-текущий-спринт-сборка.md) · [Текущая задача](sprints/00-текущая-задача.md) · [Аудит аналитики](05-аудит-аналитики-2026-07-06.md)

Контекст: собрана почти готовая версия — убран сюжет, реализован чистый free-to-play, докачаны ассеты. Цель — не добавлять фичи, а **довести существующую версию до надёжного, скучного, железно протестированного состояния** перед широким релончем на iOS + Android. Баланс и монетизацию донастраиваем по ходу тестирования, не переусложняя новыми механиками.

**Как это идёт по времени (уточнено 2026-07-06):** тестирование не блокирует релиз последовательно — оно идёт **параллельно** модерации Android в Google Play. Владелец тестирует баланс на iOS, пока Android-сборка проходит ревью; к моменту одобрения Android баланс уже проверен, остаётся только несколько дней тестирования багов перед релизом на обеих платформах. Это не открытый по времени плейтест "пока не почувствую уверенность" — естественным ограничителем служит срок модерации Android. Спешить ради красивого чекпоинта не нужно — сырая версия в бою чинится тяжелее, чем до релиза, см. [[03-отчет-владельцу-2026-07-06]].

## 1. Addressables / докачка ассетов
- [ ] Собрать финальные ассеты
- [ ] Залить на сервер
- [ ] Протестировать докачку на чистом устройстве (первый запуск без кэша)
- [ ] Проверить сценарий плохой/прерванной сети при докачке

## 2. Обновление со старых версий (совместимость) — отдельный прогон, геймплей сильно изменился
Явный риск: часть текущих ~60-150 активных пользователей в месяц открывает игру со старым сохранением/прогрессом. Нужно понять, у скольких это сломается, и что при этом произойдёт (краш, потеря прогресса, откат к дефолту).

- [ ] Сначала продумать сценарии на бумаге: какие поля/структуры данных изменились между старой и новой версией (сюжет убран, экономика могла измениться)
- [ ] Накатить новую версию поверх старой (реальный апдейт, не чистая установка) на тестовом устройстве/аккаунте со старым прогрессом
- [ ] Проверить: не крашится ли, не теряются ли купленные предметы/валюта, корректно ли мигрирует прогресс (или явно и не разрушительно сбрасывается)
- [ ] Прогнать на нескольких "возрастах" старого сохранения (сразу после установки год назад / после активной игры / после доната)
- [ ] Зафиксировать, сколько текущих активных пользователей потенциально попадают в зону риска (см. `Analytics/Scripts/metric_retention.py` — активные за последние месяцы)

## 3. Геймплей и баланс (в Unity, затем на устройстве)
Цель — надёжный баланс без дыр, уверенность что играть интересно, чёткое ощущение точек монетизации.
- [ ] Собрать билд для длительной ручной игры
- [ ] Играть регулярно **несколько недель**, чтобы прочувствовать реальный ритм (голосование за машину — сутки, это не проверяется за один присест)
- [ ] Явно выписывать точки монетизации по ходу игры: где чувствуется нехватка ресурса, где хочется купить, где раздражает
- [ ] Отдельно проверить экономику "дыр" — можно ли обойти платный контент нечестным путём, не застревает ли прогресс без доната
- [ ] **Сначала протестировать базовый баланс без смарт-задания** (см. [[hypotheses/09-смарт-задание-по-моделям]]) — это дополнительный источник монет, решение о включении в v1 (или как fast-follow сразу после) принимается только после того, как базовая экономика подтверждена рабочей, не раньше
- [ ] Параллельно: внутреннее тестирование — 2 недели, привлечь друзей как тестеров
- [ ] Опционально: собрать обратную связь от части листа ожидания игроков (1934 email, см. [[05-аудит-аналитики-2026-07-06]])

### Эталонный анализ (бенчмарк) — играть параллельно с тестированием своей версии
Идея: как художник ставит работу рядом с эталоном, чтобы увидеть разницу в качестве, хоть и в другом стиле. Другой жанр — специально, чтобы не сравнивать один в один, а прочувствовать сам игровой опыт.

| Что изучаем | Игра | На что смотреть |
|---|---|---|
| Таймер ожидания + предвкушение награды (аналог суточного голосования на Арене) | **Clash Royale** | Момент проверки таймера, ощущение "скоро откроется" |
| Тот же таймер, препарировать психологию возврата (не как фанат, как инженер) | **Coin Master** | Что именно заставляет открыть приложение именно сейчас |
| Долгий цикл + ускорение за премиум-валюту (аналог буста голосования за кристаллы) | **Township / Hay Day** | Момент, где хочется заплатить, чтобы не ждать |
| Привязанность к коллекции (аналог "машины как питомцы") в другом жанре | **CSR Racing 2** | Ощущение "своей" машины, тюнинг как вложенная идентичность |
| Нарратив НЕ в ущерб темпу геймплея (контраст с провалившейся историей про дедушку) | **Homescapes / Gardenscapes** | Как история вплетена в награды, а не идёт вместо core loop |
| Первые минуты — обучение через действие, быстрые победы | **Candy Crush, Clash Royale** | Одна механика за раз, к "вкусу" ценности — как быстро |

- [ ] Играть каждую из выбранных игр параллельно с тестированием своей версии (не обязательно все 6 — можно выбрать 2-3 приоритетных)
- [ ] Вести короткий дневной лог: что зацепило, в какой момент захотелось вернуться, где споткнулся, где почувствовал стартовый оффер
- [ ] Ориентир по цифрам ретеншена (не только "на глаз"): здоровый D1 30-40%, D7 15-25%, D30 5-10% — сверять с [[05-аудит-аналитики-2026-07-06]] и с новыми когортами после релонча

### Стартовый оффер ("невозможно отказаться") — конкретика к пункту про монетизацию выше
- Цель первой покупки — не заработок на ней самой, а слом психологического барьера "я плачу в этой игре" (конверсия в повторные покупки после первой — в 5-10 раз выше).
- Цена $0.99–$4.99, ценность **грубо превосходит** цену (гарантированный редкий/эксклюзивный контент + пачка мягкой валюты), опционально ограничение по времени.
- Разместить **после** первого "вкуса" ценности (первая собранная машина), а не вместо/до него — это и есть практическая реализация [[hypotheses/02-смягчить-пейвол]].
- [ ] Спроектировать конкретный стартер-пак (что входит, цена, момент показа) во время эталонного анализа выше

## 4. Push-уведомления (решено делать сейчас, не откладывать)
- [ ] Механика: "Ваша машина получила рейтинг. Заберите награду" — ключевой пуш под ритм Арены (сутки на голосование)
- [ ] Проверить, что push-токены действительно собираются и доходят (в БД поле `devices.pushToken` есть, см. [[hypotheses/05-push-уведомления-как-рычаг-ретеншена]])
- [ ] Протестировать доставку на реальном устройстве (не только в тесте/эмуляторе)
- [ ] UI/экран настроек пушей можно отложить в параллельный трек (см. ниже) — сама механика доставки не блокируется дизайном экрана

## 5. Туториал
- [ ] Туториал должен стартовать сразу при первом запуске, без промежуточных экранов
- [ ] Экран/кнопки — см. [[../00-описание-проекта]] (решено: текстовая подпись, не кнопка; крестик скрыт на первом прохождении)
- [ ] Проверить на чистой установке (не только апдейт поверх существующего прогресса)

## 6. Реклама (rewarded, Google)
- [ ] **Проверить, активен ли аккаунт AdSense/AdMob** — отдельный аккаунт от Google Play Developer, легко забыть (см. [[09-операционный-чеклист]]). Без него реклама не покажется, даже если код рабочий
- [ ] Сейчас проверено только в тестовом режиме — обязательно проверить **на реальном устройстве** до релиза
- [ ] Проверить полный цикл: показ → досмотр → начисление награды → отсутствие дублей/зависаний

## Параллельный трек (не блокирует тестирование выше, делается пока владелец играет и тестирует баланс)
- [ ] Стартовый экран (пока не готов)
- [ ] Обновлённый дизайн главного экрана (сейчас сырой)
- [ ] UI-экран пуш-уведомлений/настроек

## Не в этом заходе (сознательно отложено)
- Ролики на новые темы, новые фичи в маркетинге сверх промокодов
- Топ недели/дня (ждём, пока появится объём игроков)
- Доработка реплеев для автогенерации контента
- Win-back по листу ожидания, активация LinkedIn-сети — см. [[08-маркетинг-план]], раздел "сознательно не делаем сейчас"

Промокоды (см. [[hypotheses/07-промокоды-сразу-параллельно]]) строятся параллельно, не блокируют тестирование геймплея.
