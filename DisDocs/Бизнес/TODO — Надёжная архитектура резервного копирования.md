# TODO: надёжная архитектура резервного копирования

Цель — постепенно выстроить систему хранения без единой точки отказа. Потеря Mac, внешнего диска, доступа к iCloud, GitHub, Timeweb или SafeInCloud не должна приводить к потере проекта, документов или доступов.

## Базовый принцип

Для критичных данных использовать схему 3–2–1:

- минимум три копии;
- минимум на двух разных носителях;
- минимум одна копия вне дома или в независимом облаке.

Синхронизация не считается полноценным бэкапом: удаление или повреждение файла может распространиться на все синхронизируемые устройства.

## 1. Пароли и SafeInCloud 2

Четырёхзначный мастер-пароль слишком слабый: это только 10 000 вариантов. Если злоумышленник получит файл зашифрованной базы, пароль можно перебирать офлайн.

- [ ] Заменить четыре цифры на длинную запоминаемую фразу из 5–6 случайных слов.
- [ ] Не использовать цитату, дату, имя или повторно используемый пароль.
- [ ] Включить Touch ID / Face ID для быстрого ежедневного доступа.
- [ ] Записать мастер-пароль SafeInCloud на бумаге и хранить в защищённом месте.
- [ ] Не хранить единственную копию мастер-пароля внутри SafeInCloud.
- [ ] Не использовать мастер-пароль SafeInCloud как пароль Time Machine.
- [ ] Настроить SafeInCloud на автоматический запуск на Mac.
- [ ] Проверять дату последней локальной копии базы.
- [ ] По возможности хранить облачную базу SafeInCloud не только в iCloud: использовать Google Drive, Dropbox, OneDrive или WebDAV/NAS.

SSH-ключи можно перевыпустить. В SafeInCloud достаточно хранить их назначение, host, username и passphrase. При замене Mac можно создать новый ключ, добавить его публичную часть на сервер и удалить старый ключ.

## 2. Актуальные документы на Mac

Отключить `Optimize Mac Storage` для iCloud, чтобы актуальные документы физически находились и на Mac, и в iCloud. Time Machine не должна зависеть от облачных placeholder-файлов.

- [ ] Отключить оптимизацию хранилища iCloud.
- [ ] Дождаться полной загрузки важных iCloud-файлов на Mac.
- [ ] Проверить отсутствие значков облака у критичных папок.
- [ ] Держать на Mac актуальные документы и активные проекты.
- [ ] Завершённые проекты переносить в архив только после проверки нескольких копий.

Предлагаемая локальная структура:

```text
~/Documents_local/
├── Projects/
├── Music/
├── Writing/
├── Legal/
├── Finance/
├── Backups/
│   └── Scrivener/
└── Exports/
    ├── Apple Notes/
    ├── SafeInCloud/
    └── Git Bundles/
```

iCloud Drive и Dropbox можно продолжать использовать для синхронизации, но у важных данных должна быть физическая локальная копия.

## 3. Отдельный диск Time Machine

Для Mac с накопителем 512 ГБ:

- 512 ГБ — недостаточно для нормальной глубины истории;
- 1 ТБ — минимальный разумный размер;
- 2 ТБ — предпочтительный размер с учётом документов и отключения оптимизации iCloud.

HDD подходит для стационарного Time Machine. SSD быстрее и устойчивее к ударам, но не обязателен.

- [ ] Купить или выделить отдельный диск 1–2 ТБ только для Time Machine.
- [ ] Отформатировать его средствами macOS для Time Machine.
- [ ] Включить шифрование.
- [ ] Сохранить пароль диска в SafeInCloud.
- [ ] Вторую копию пароля записать на бумаге.
- [ ] Подключать диск регулярно либо держать подключённым в рабочем месте.
- [ ] Проверить восстановление нескольких документов из Time Machine.

Пароль Time Machine и мастер-пароль SafeInCloud должны быть разными. Бумажная копия устраняет замкнутый круг, когда для восстановления SafeInCloud нужен пароль от Time Machine, хранящийся только в SafeInCloud.

## 4. Второй внешний диск для архивов

Использовать отдельный существующий диск или SSD для завершённых проектов и контрольных копий:

```text
Archive/
├── 2026/
│   ├── Projects/
│   ├── Music/
│   ├── Writing/
│   ├── Notes/
│   ├── Scrivener/
│   ├── Git/
│   └── SafeInCloud/
└── manifests/
```

- [ ] Определить отдельный физический диск для архива.
- [ ] Создавать датированные копии, не перезаписывая единственный архив.
- [ ] Добавлять контрольные суммы или manifest файлов.
- [ ] Не удалять исходник автоматически после копирования.
- [ ] Сначала проверить локальный архив и удалённую копию, затем освобождать место вручную.
- [ ] Не держать архивный диск постоянно подключённым.
- [ ] По возможности хранить его отдельно от Mac и Time Machine-диска.

## 5. Удалённая копия архивов

Использовать отдельное облако объёмом до 2 ТБ, например Облако Mail.ru, как копию вне дома. Это защищает от пожара, кражи и одновременной потери Mac и внешних дисков.

- [ ] Купить или освободить до 2 ТБ независимого облачного пространства.
- [ ] Не синхронизировать единственную архивную папку в режиме, где удаления немедленно распространяются в облако.
- [ ] Загружать датированные версии архивов.
- [ ] Конфиденциальные архивы шифровать локально до загрузки.
- [ ] Пароль шифрования хранить в SafeInCloud и на бумаге.
- [ ] Настроить срок хранения нескольких поколений архивов.
- [ ] Периодически проверять скачивание и открытие файлов из облака.

Пример имён:

```text
CarDesign-2026-08.bundle
Documents-2026-08.tar
Music-project-name-2026-08.tar
Notes-2026-08/
SafeInCloud-2026-08/
```

## 6. Git-проекты

Основная схема:

```text
GitHub → основной репозиторий
GitLab.com → приватное онлайн-зеркало
Git bundle → внешний архивный диск и удалённое облако
```

Текущая история `cardesign` занимает около 3,8 ГБ и не использует Git LFS. Бесплатный GitLab.com предоставляет 10 ГБ на проект, поэтому сейчас его достаточно для зеркала, но размер нужно контролировать.

- [ ] Создать приватное зеркало `cardesign` на GitLab.com.
- [ ] Настроить отправку всех веток и тегов на GitHub и GitLab.
- [ ] Не вести параллельную разработку в зеркале.
- [ ] Проверять размер репозитория раз в несколько месяцев.
- [ ] Создавать полный Git bundle ежемесячно и перед крупными инфраструктурными изменениями.
- [ ] Проверять каждый bundle командой `git bundle verify`.
- [ ] Хранить bundle на архивном диске и в удалённом облаке.

Git bundle содержит ветки, теги, commit’ы и достижимые Git-объекты, но не включает незакоммиченные изменения, staging area, локальные конфиги, hooks и игнорируемые файлы. Рабочая папка дополнительно защищается Time Machine.

## 7. Специальные типы данных

### Scrivener

Dropbox-синхронизация не заменяет backup.

- [ ] Включить встроенные автоматические ZIP-бэкапы Scrivener.
- [ ] Сохранять их в `~/Documents_local/Backups/Scrivener/`.
- [ ] Включить эту папку в Time Machine и архивный скрипт.
- [ ] Не копировать открытый `.scriv` как единственную резервную копию.

### Музыкальные проекты

- [ ] Перед архивированием собрать внешние аудиофайлы и сэмплы внутрь проекта (`Collect`, `Consolidate` или аналогичная команда программы).
- [ ] Проверить открытие проекта после переноса в отдельную папку.
- [ ] Хранить завершённый проект на архивном диске и в удалённом облаке.

### Apple Notes

- [ ] Продолжать периодический ручной экспорт.
- [ ] Складывать экспорты по датам: `Exports/Apple Notes/YYYY-MM-DD/`.
- [ ] Добавить экспорт заметок в регулярный архивный процесс или напоминание.

### SafeInCloud

- [ ] Хранить локальную копию базы в папке, попадающей в Time Machine.
- [ ] Убедиться, что Mac-приложение периодически запускается и синхронизирует свежую базу.
- [ ] Копировать датированный backup SafeInCloud на архивный диск и в удалённое облако.

## 8. Будущий архивный скрипт

Скрипт должен:

1. Проверять подключение нужного внешнего диска.
2. Проверять, что важные iCloud-файлы скачаны локально.
3. Копировать выбранные документы и завершённые проекты в датированную папку.
4. Создавать Git bundle для важных репозиториев.
5. Добавлять экспорт Apple Notes и локальный backup SafeInCloud.
6. Вычислять контрольные суммы.
7. Формировать читаемый отчёт о том, что скопировано и что пропущено.
8. Ничего не удалять автоматически.
9. Отдельным шагом шифровать и загружать архив в удалённое облако.

### Этап 4 — архивы

- [ ] Организовать `Documents_local` и архивный диск.

- [ ] Составить точный список архивируемых папок.
- [ ] Сделать архивный скрипт без автоматического удаления.

### Этап 5 — внешняя копия

- [ ] Подключить независимое облако до 2 ТБ.
- [ ] Настроить клиентское шифрование архивов.
- [ ] Загрузить первую полную копию.
- [ ] Проверить восстановление из удалённого облака.

## Целевая схема

```text
Актуальные данные:
Mac → iCloud/Dropbox → Time Machine

Архивные данные:
Mac → внешний архивный диск → зашифрованная копия в удалённом облаке

Пароли:
SafeInCloud с сильной фразой
→ независимое облако
→ локальный backup в Time Machine
→ мастер-пароль на бумаге

Код:
GitHub → GitLab.com → Git bundle на архивном диске и в удалённом облаке
```
