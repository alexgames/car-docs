# Следующий спринт: тестирование баланса + сборка Android

Связано с: [Текущий спринт (сборка)](01-текущий-спринт-сборка.md) · [План тестирования](../07-план-тестирования.md) · [Маркетинговый план](../08-маркетинг-план.md) · [Отчёт владельцу](../03-отчет-владельцу-2026-07-06.md)

## Когда начинается
Как только билд iOS из [[01-текущий-спринт-сборка]] собран (addressables + стартовый экран готовы) и таблицы экономики пересчитаны. Ориентировочно (не обязательство, а грубая прикидка, чтобы иметь в виду масштаб) — **несколько недель** от старта: сама многонедельная игра для проверки баланса занимает время по своей природе (нужно прочувствовать ритм суточного голосования на Арене), плюс параллельно готовится Android. Не превращать эту оценку в дедлайн — см. [[../03-отчет-владельцу-2026-07-06]] про отказ от преждевременных календарных прогнозов.

## 3. Сборка iOS готова → тестирование баланса
- [ ] Ручная игра владельцем несколько недель — баланс, точки монетизации (см. методику в [[../07-план-тестирования]], включая эталонный анализ игр-бенчмарков и дизайн стартер-пака)
- [ ] Внутреннее тестирование с друзьями (2 недели, параллельно)
- [ ] Туториал сразу при первом запуске + кнопка "повторить"

### Push-уведомления (небольшая, но важная задача — не откладывать)
Решено делать в этом спринте, не позже: механика "ваша машина получила рейтинг, заберите награду" — под ритм суточного голосования Арены.
- [ ] Проверить, что push-токены реально собираются и доходят (поле `devices.pushToken` в БД есть, см. [[../hypotheses/05-push-уведомления-как-рычаг-ретеншена]])
- [ ] Реализовать отправку
- [ ] Протестировать доставку на реальном устройстве (не только в тесте/эмуляторе)

### Голосовалка (Arena) — небольшая, но важная задача, если будет такое решение
Владелец отметил это как небольшую, но важную задачу. **Скоуп ещё не уточнён** — не придумываю за владельца детали, фиксирую как открытый пункт до уточнения. Кандидат на связь: механика голосования на Арене (обязательное голосование за N чужих работ перед публикацией своей — см. исторический дизайн-документ, упомянутый в [[../hypotheses/09-смарт-задание-по-моделям]] и смежных заметках).
- [ ] Уточнить у владельца конкретный скоуп задачи
- [ ] Решить, делать ли в этом спринте или переносить

## 4. Android-сборка
🔴 **Часть этого — срочная и не ждёт остального спринта, см. [[00-текущая-задача]].** Google закрывает Play Console аккаунты без ни разу отправленного на ревью приложения (см. [[../09-операционный-чеклист]]). Минимальный шаг (собрать то, что есть сейчас, залить в Internal/Closed testing) нужно сделать в ближайшие дни, не дожидаясь баланса/push/остального ниже. Дальше, уже не срочно, полноценная Android-сборка для реального релиза:
- [ ] Собрать Android-билд
- [ ] Проверить платформенные особенности (размер сборки, специфичные баги)

## 5. Тестирование Android (для полноценного релиза, не для срочной задачи выше)
- [ ] Rewarded-реклама (Google) — проверить на реальном устройстве, не только в тесте
- [ ] Собрать и отправить Android-сборку на модерацию в Google Play

## 5-2. Параллельно с шагом 5 — контент и запуск воронки маркетинга
См. [[../08-маркетинг-план]] и [[../10-маркетинг-банк-идей]] за деталями.
1. [ ] Заполнить `Cont-plan` роликами из `topics`/`vert_video`, собрать батч ~60 роликов (уже идёт с шага 1)
2. [ ] **Зафиксировать дату запуска/возобновления постинга в соцсетях**
3. [ ] **Первая неделя после запуска** — смотрим динамику просмотров. Решение по факту: оживлять текущие аккаунты регулярным постингом или заводить новые (соцсети могли не дать никакого трафика после долгого простоя — узнаем только по факту)
4. [ ] **Собрать статистику из соцсетей за первую неделю** (API соцсетей или CSV из сервиса автопостинга) — пока вручную, позже настроить/встроить в воронку
5. [ ] **Построить воронку**: просмотры → переходы → инсталлы → активные игроки → платежи (сначала руками, потом думать про автоматизацию/дашборд). Смотрим рост и улучшение каждого шага, не абсолютную сумму

Дополнительно, не блокирует:
- [ ] Восстановить подписки на сервисы автопостинга и музыку — когда контент-буфер готов к публикации (см. [[../09-операционный-чеклист]])
- [ ] Обновить ASO (скриншоты, метаданные — см. [[../08-маркетинг-план]])
- [ ] Синхронизировать первую волну контента с датой релиза на Android
- [ ] **Зарезервировать контент для промо** — список конкретных премиум-машин/деталей, явно исключённых из других продаж (см. [[../hypotheses/14-промокоды-чертеж-паззл]])

## Цель: переоценка прибыли

- [ ] По накопленным неделям данных воронки — построить обоснованный денежный прогноз (не раньше и не позже: не гадать без данных, но и не откладывать бесконечно, когда данные уже есть)
