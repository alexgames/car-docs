# Инструмент делегирования записи роликов (Android-only) — отложено

⚠️ **Отложено 2026-07-19.** Вместо делегирования выбран план "1 ролик/день, весь год, лично" — см. [[../08-маркетинг-план]]. Выгорание решается вариативностью инструмента (экран выбора режима, референсы), не делегированием — см. [[../inspiration/01-контент-конвейер-ролики-и-инспирация]]. Идея не отменена — если план самостоятельной записи не сработает или появятся деньги на помощника, можно вернуться к этому документу.

Связано с: [Маркетинговый план](../08-маркетинг-план.md) · [Маркетинговый банк идей](../10-маркетинг-банк-идей.md) · [Тестирование баланса + Android](02-следующий-спринт-баланс-и-android.md)

## Проблема, которую решаем
Сейчас весь конвейер роликов (запись геймплея в специальном режиме в Unity → монтаж → музыка → постинг) держится на владельце лично — именно это и вызывало выгорание в прошлом (монотонная ручная работа без делегирования). Нужен способ снять с себя рутинную часть (сборку машин на камеру), оставив себе только развитие инструмента — то, что нравится и не выгорает.

## Ограничение, которое не дало сделать это раньше
- Исходники Unity-проекта отдавать нельзя (это ядро бизнеса).
- Десктопное Mac-приложение можно защитить и раздать, но: (а) мало у кого есть Mac, (б) под Windows игра не работает из-за сторонней библиотеки (возможно, и на Mac тоже не работает в собранном виде — не проверено, нужно уточнить).
- Мобильный Android APK, защищённый паролем, — реалистичный вариант раздачи исполнителю, но готовый ролик как секвенция PNG-кадров — это пара сотен мегабайт, неудобно передавать с телефона на сервер.

## Решение: спец-приложение для Android с записью через реплей-конфиг, а не PNG
Только Android — не iOS/Mac, по причинам выше.
- Отдельная (не основная) сборка игры под Android, вертикальная, с дополнительным инструментом записи: настройки + кнопка старт/стоп.
- Использует уже существующую систему реплеев (см. [[../hypotheses/09-смарт-задание-по-моделям]] — смежная, но отдельная тема): записывать **полный конфиг на каждый кадр**, включая угол камеры, а не сами кадры.
- Итог — не видеофайл и не PNG-секвенция, а **JSON** с записанной формулой ролика — маленький файл, легко залить на сервер даже с телефона.
- Финальный рендер видео из JSON-реплея, монтаж, музыка, постинг — остаются полностью на стороне владельца, уже автоматизированы (см. [[../08-маркетинг-план]]) и не меняются.

## Режимы записи (спланировать все, выбрать самые простые для реализации)
1. **Все возможные режимы для записи видео** — сначала расписать полный список (в духе уже собранного банка форматов, см. [[../10-маркетинг-банк-идей]], `topics`/`vert_video`), потом выбрать самые простые в реализации для первой версии инструмента, не пытаться сделать все сразу.
2. **"Собери по референсу"** — половина экрана занята фото-референсом, исполнитель повторяет его в редакторе. Усложнение по сравнению с обычной записью: если ролик сохраняется скриптом (JSON-реплей), то само референсное фото тоже нужно отправлять на сервер вместе с JSON — иначе при финальном рендере видео нечем будет проиллюстрировать "было/стало". Не сложно, но отдельная новая фича (загрузка фото + привязка к конкретной записи), не входит в базовый JSON-реплей автоматически.
3. **Самый простой вариант — не через JSON-реплей вообще.** Записать обычный летсплей из стандартной **горизонтальной** версии игры (экранная запись, не вертикальный спец-режим) и выложить как обычное видео на YouTube. Не даёт вертикального формата для Shorts/TikTok/Reels, зато не требует вообще никакой новой инфраструктуры (ни JSON-реплея, ни серверной приёмки) — годится как самый дешёвый первый шаг, параллельно с проектированием остального.

## Экономика
- Исполнитель — школьник/студент, не нужна особая компетенция: примеры роликов есть в сети, объяснить легко, работа несложная.
- Ориентир: ~200 руб за ролик, 10 роликов за несколько часов работы ≈ 2000 руб.
- Владелец отсматривает и отбирает лучшие из присланных.
- 30 роликов ≈ 6000 руб — по факту копейки относительно ценности регулярного потока контента.
- При таком подходе реалистичен темп 2-3 выпущенных ролика в день, не завязанный на личное время и настроение владельца.
- Ролики примерно одного визуального качества (не съёмка на камеру, а рендер из игры) — предсказуемый результат, не лотерея по качеству.

## Что нужно придумать/сделать (объём работ будущего спринта)
1. **Задание для исполнителя** — придумать формат "сборки по заданию" так, чтобы исполнитель понимал, что именно строить на камеру (пересекается с механикой смарт-заданий/тематических заданий, см. [[../hypotheses/09-смарт-задание-по-моделям]], но это отдельная от них задача — не путать разработку одного с другим).
2. **Инструмент записи**: настройки, старт/стоп, запись полного конфига по кадрам (камера + всё остальное) в JSON.
3. **Отдельная Android-сборка** только с этим режимом, защищённая паролем, без передачи чего-либо, что раскрывает основной продукт сверх необходимого.
4. **Простая инструкция** для исполнителя — работа не компетентная и не сложная, объяснить по референсам из сети.
5. **Приёмка**: загрузка JSON на сервер, отсмотр и отбор владельцем, дальше — существующий автоматизированный рендер/монтаж/постинг без изменений.

## Почему это не срочно и делается после текущего
- Текущий 60-роликовый батч **уже налажен и идёт** личными силами владельца — этого достаточно, чтобы закрыть минимальный поток трафика на ближайшее время.
- Приоритет №1 сейчас — сам продукт (геймдизайн — слабое место, см. [[../07-план-тестирования]]) и Android-релонч.
- Делегирование записи роликов — это решение для устойчивости на дистанции (защита от будущего выгорания) и удешевления контента, а не для сиюминутной проблемы с трафиком.
- **Порядок:** сначала закончить [[01-текущий-спринт-сборка]] и [[02-следующий-спринт-баланс-и-android]] → посмотреть на цифры → затем взяться за эту задачу по маркетингу. Не раньше.

## Явно отделяем от "коллабов"
Сбор трекера по `collabs`/`links` — тоже вынесен из текущего фокуса, но по другой причине: это ручная, небыстрая работа, а не инструмент. Кроме того, коллабы имеет смысл начинать, когда проект уже "живой" и с более крупной аудиторией в соцсетях — сейчас для этого не время в любом случае. Обе задачи — в спокойном режиме, без давления по срокам, но это два разных направления, не путать в одну задачу.
